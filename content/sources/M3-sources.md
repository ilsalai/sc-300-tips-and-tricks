# M3 Sources: Plan and implement workload identities (20 a 25%)

Fuente de verdad del alcance: skills outline oficial "as of April 27, 2026".
https://learn.microsoft.com/credentials/certifications/resources/study-guides/sc-300

Learning path oficial del dominio (4 módulos: dos de enterprise apps y SSO, dos de app registration):
https://learn.microsoft.com/training/paths/implement-access-management-for-apps/

Ojo: ese learning path **no trae módulo propio de managed identities ni de Defender for Cloud Apps**. Abajo se indica, por subdominio, qué módulo de Learn sí lo cubre.

Cómo se validaron los deep links: cada página se leyó con la herramienta de Microsoft Learn (fetch o búsqueda oficial) y el anchor se tomó del heading real (minúsculas, espacios a guiones, sin signos). Casi todos los anchors salieron idénticos en los resultados del buscador oficial de Learn.

Notas de vigencia (septiembre 2026):
- La documentación de Application Proxy vive ahora en `/entra/identity/app-proxy/`. Los connectors se llaman **Microsoft Entra private network connectors** y son los mismos que usa Private Access.
- Las apps de Application Proxy con pre-auth de Entra ya no usan el secreto CWAP: usan **Federated Identity Credentials**. Una app de App Proxy se borra desde Enterprise applications, no desde App registrations.
- En User consent settings existe la opción **Let Microsoft manage your consent settings**, que es el default en tenants nuevos. Las otras opciones siguen: no permitir, verified publishers con permisos seleccionados, o permitir todo.
- **Risk-based step-up consent** viene activo por default, pero solo cambia algo si el user consent está habilitado.
- Defender for Cloud Apps se administra desde el portal de Microsoft Defender (security.microsoft.com), en Cloud Apps. Si app governance está activo, las OAuth app policies se crean desde **App governance**.
- Conditional Access app control ya protege Edge for Business "en el navegador" (candado en la barra, sin sufijo `.mcas.ms`). Los demás navegadores siguen por reverse proxy con `.mcas.ms`.
- La página **Files** de Defender for Cloud Apps se deprecó el 1 de septiembre de 2024.

Bullets sin página única en Learn (cómo se resolvieron):
- "Application-level and tenant-level settings": no hay una página con ese nombre. Se mapeó a las propiedades de la enterprise app (nivel app) y a User settings, consent settings y admin consent workflow (nivel tenant).
- "Classify" en "assign, classify and manage users, groups and app roles": se interpretó como **permission classifications** (clasificar permisos como low impact para el user consent), que es lo único en Learn con ese verbo en enterprise apps.
- "Plan app registrations": no hay página de planeación como tal. Se mapeó a application object vs service principal, supported account types y quién puede registrar apps.
