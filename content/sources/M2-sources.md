# M2 Sources: Implement authentication and access management (25 a 30%)

Fuente de verdad del alcance: skills outline oficial "as of April 27, 2026".
https://learn.microsoft.com/credentials/certifications/resources/study-guides/sc-300

Ojo con el peso: el "Skills at a glance" dice 25 a 30%, pero el título del detalle del mismo study guide dice 20 a 25%. Para estudiar, trátalo como **el dominio más pesado del examen**.

Learning path oficial del dominio (6 módulos):
https://learn.microsoft.com/training/paths/implement-authentication-access-management-solution/

El módulo "Implement access management for Azure resources" viene en el learning path pero no mapea a ningún bullet de este dominio en el outline 2026. Queda como lectura opcional.

Cómo se validaron los deep links: cada página se leyó completa con la herramienta de Microsoft Learn y el anchor se armó con el texto real del heading (minúsculas, espacios a guiones, sin signos). Varios anchors además salieron idénticos en los resultados del buscador oficial de Learn o en links internos de las mismas páginas.

Notas de vigencia (septiembre 2026):
- Desde el 30 de septiembre de 2025 los métodos ya no se administran en las políticas legacy de MFA y SSPR. Todo va en la **Authentication methods policy**. Lo único que sigue en la política legacy de SSPR: security questions, "Number of methods required to reset" y la política de reset para admins.
- **Report suspicious activity** reemplazó a Fraud alert, Block/unblock users y Notifications (retirados el 1 de marzo de 2025).
- Passkeys ahora se configuran con **passkey profiles** (hasta 3, incluyendo el Default). Los passkeys de Microsoft Authenticator se habilitan en la política Passkey (FIDO2), no en la política de Microsoft Authenticator.
- La registration campaign ya puede empujar Microsoft Authenticator o passkey, un método a la vez. Learn avisa que el rollout termina a fin de septiembre de 2026 y el portal puede verse distinto mientras tanto.
- Las políticas de riesgo legacy de ID Protection se retiran el **1 de octubre de 2026**. La recomendación es Conditional Access con el grant nuevo **Require risk remediation**.
- El grant "Require approved client app" se retira (marzo 2026). Para políticas nuevas se usa "Require app protection policy".
- El outline dice "OAuth 2.0 tokens". En Learn, el método de autenticación se llama **OATH tokens** (TOTP de hardware o software). Aquí se cubren las dos lecturas: OATH como método y el ciclo de vida de tokens OAuth 2.0 (access, refresh, session) con sign-in frequency.
- "Internet Access for Microsoft 365" hoy aparece en Learn como **Microsoft Entra Internet Access for Microsoft services** y se implementa con el Microsoft traffic profile, incluido en Entra ID P1.
- "Implement device-enforced restrictions" no tiene una página propia en Learn. Se mapeó a los controles de CA que dependen del estado del device: grant compliant o hybrid joined, filter for devices, app enforced restrictions y la user action Register or join devices.
