Una identidad para todo el scale set

Scale set instances are re-created daily. One shared identity, pre-authorized to Key Vault, no secrets. Which identity?

User-assigned managed identity assigned to the scale set

B

System-assigned managed identity on each instance

C

App registration with a client secret in app settings

D

Synced AD user account used as a service account

Por qué

La user-assigned tiene ciclo de vida independiente y se asigna a muchos recursos. Learn la pone para pre-autorizar y para recursos que se reciclan seguido.

B. Nace y muere con cada instancia, y no existe antes del deploy.

C. Funciona, pero obliga a manejar y rotar un secreto.

D. User accounts como service accounts no se recomiendan.

Learn: System-assigned vs user-assigned

17 / 27

Debrief de 30 segundos. Frase clave: "User-assigned es roomie: la compartes y la borras tú". Delata: "re-created", "same identity" y "before the new instances are deployed". Si muchos eligieron B, recordar que la system-assigned no se puede pre-autorizar porque todavía no existe.
